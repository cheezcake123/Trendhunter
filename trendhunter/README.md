# TrendHunter v2.4.0

바이낸스 자동매매 봇. 서버(우분투)에서 24시간 돌고, 텔레그램으로 조작합니다.
돈을 두 바구니로 나눠 운용합니다.

- **현물 50%**: 거래대금 상위 6개 메이저 코인의 추세 모멘텀(20·60·120·250일) + 변동성 맞춤 비중 + BTC 추세 게이트. 매일 09:05 KST 한 번 리밸런싱. 레버리지 없음.
- **선물 50%**: 일봉 정배열 + 4시간봉 40봉(약 7일) 고점 돌파 롱, 거래소 손절(Algo Order) + 5 ATR 추적 손절. 선택: 불타기(수익 중 추가 진입).
- 두 지갑 비율은 범용 이체로 자동 유지 (목표에서 10%p 이상 벗어나면, 매월 1일에는 2%p 이상이면).

자세한 설치·운영·전략 설명과 전략 비교 결과는 Claude가 함께 만든 설명서를 보세요.

## v2.4 변경점
바이낸스 실제 캔들(2020-01 ~ 2026-11, 6종목)로 다시 검증했습니다. 펀딩비는 8시간 0.03% 고정으로 가정했고, 이 가정에서 v2.3의 실제 펀딩비 결과와 거의 같은 값이 나옵니다(선물 연 +84% / 최대낙폭 -45%). 서버의 `/backtest`는 실제 펀딩비를 씁니다.

- **불타기(피라미딩) — 기본 꺼짐.** 켜기: `/preset`에서 단계를 고르거나 `/set pyramid_max_adds 2`.
  - 언제: 손절이 평균 진입가 이상으로 올라와 있고(지금 손절돼도 손실이 아님), 4시간봉 종가가 마지막 진입가보다 1.5R(R = 첫 진입의 손절 폭) 이상 더 갔을 때. 봉 하나에 한 번, 포지션당 최대 2회.
  - 얼마나: 추가분이 지금 손절가까지 밀리면 잔고의 '1회 위험'만큼 잃는 수량. 첫 진입보다 크게 잡지 않고, 종목당 증거금 한도(잔고의 30%)와 청산가 여유 안에서만 삽니다.
  - 추가한 뒤 손절 주문을 전체 수량으로 다시 겁니다(포지션당 손절 1개). 본전 보호·추적 손절은 평균 진입가 기준으로 다시 계산합니다.
  - 결과를 모르는 추가 주문은 다시 보내지 않습니다. 나중에 체결된 것이 확인되면 수량·평균가를 거래소 값으로 맞추고 손절을 다시 겁니다.
  - 일시정지·일일 손실 한도·연패 휴식·자본 바닥선에 걸려 있으면 추가하지 않습니다. 모의 모드는 가상 체결만 합니다.
  - 검증(선물만): 1회 위험 3%·불타기 없음 연 +84% / 최대낙폭 -45% → 1회 위험 2%·불타기 2회 연 +95% / -42%.
    2024~26년은 +45% / -45% → +72% / -39%, 2020~23년은 +119% / -40% → +114% / -42%로 비슷합니다.
  - 약점: 추세가 짧게 끊기는 해에는 불리합니다(2023년 +78% vs +33%). 돌파 기간·추적 폭을 바꾼 6가지 규칙, 종목을 하나씩 뺀 6가지, 10종목, 손절 미끄러짐 가정에서 다시 돌렸을 때 대부분 나아졌지만 돌파 30봉·추적 4 ATR 조합에서는 비슷하거나 낮았습니다.
- **위험 단계(`/preset`)를 불타기 포함으로 다시 맞췄습니다.** 과거 최대낙폭이 예전 단계와 같거나 작도록 1회 위험을 낮췄습니다. 업데이트만으로는 아무것도 바뀌지 않고, 단계를 골라야 적용됩니다.

  | 단계 | 현물 : 선물 | 선물 1회 위험 | 불타기 | 과거 최대낙폭 | 2024~26 연수익 | 전체 연수익 |
  |---|---|---|---|---|---|---|
  | 안정 | 70 : 30 | 2% | 2회 | -28% | +42% | +75% |
  | 기본 | 50 : 50 | 2.5% | 2회 | -35% | +60% | +96% |
  | 공격 | 40 : 60 | 3% | 2회 | -41% | +74% | +115% |

  예전 '기본'(50 : 50, 3%, 불타기 없음)은 같은 계산으로 -35% / +38% / +76%입니다.
- **증거금 규칙(`liq_buffer_mult`, 기본 2).** 포지션 크기와 손절은 그대로 두고 격리 증거금만 줄입니다: 청산가가 손절 폭의 2배 이상 떨어져 있는 한도에서 가장 높은 레버리지를 씁니다(상한 `max_leverage`). 격리 증거금은 손절이 미끄러지거나 체결되지 못했을 때 그 포지션에서 잃을 수 있는 최대 금액이라, 보통 잔고의 30% → 15% 안팎으로 줄어듭니다. 진입 알림의 레버리지 숫자는 커지지만 손절 위험과 백테스트 손익은 같습니다. 불타기에 쓸 증거금 여유도 여기서 나옵니다. 예전 방식: `/set liq_buffer_mult 0`.
- **캔들 재시도.** 4시간봉 마감 때 캔들을 받지 못한 종목은 마감 후 10분까지 30초마다 다시 확인합니다. 전에는 그 봉의 신호를 통째로 놓쳤습니다. 방금 마감한 봉이 아직 도착하지 않았을 때 이전 봉을 새 봉으로 판단하던 틈도 막았습니다.
- 청산가가 손절가보다 먼저 닿는 위치가 되면 경고합니다(펀딩비로 증거금이 줄었거나 앱에서 레버리지를 바꾼 경우).
- **기대치 주의.** 과거 평균은 2020~21, 2024년 같은 큰 상승장이 끌어올린 숫자입니다. 2025년 이후만 보면 기본 단계가 연 +12% / 최대낙폭 -29%, 2026년은 11월까지 손실 구간입니다. 종목과 규칙을 지금 시점에서 골랐다는 점도 과거 수치를 실제보다 좋게 만듭니다.
- 검증에 쓴 스크립트: 저장소의 `research/lab.py`(배포 zip에는 들어가지 않습니다).

## v2.3 변경점
- **현물 남는 USDT 이자 예치(Simple Earn 유연, USDT)** — 기본 꺼짐, 켜기: `/set spot_earn true`.
  - 매일 09:05 리밸런싱 때 매수·선물 이체에 필요한 만큼 먼저 환매하고, 다 끝난 뒤 남는 USDT를 예치합니다(현물 지갑에 2 USDT 남김, 상품 최소 금액 미만은 예치 안 함).
  - 예치한 USDT도 현물 평가금액·/status·/pnl·현물/선물 배분 계산에 포함됩니다. 잔고 조회가 실패하면 마지막으로 확인한 금액을 씁니다.
  - 예치·환매가 실패해도 매매·이체·선물 손절 관리는 그대로 진행하고, 알림만 보낸 뒤 다음 날 다시 시도합니다. 예치·환매는 하루 몇 번뿐이고 대기 시간에도 상한이 있습니다.
  - 예치할 때 `autoSubscribe=false`로 보내 바이낸스가 현물 지갑을 자동으로 쓸어 가지 않게 합니다.
  - 필요한 API 권한: 'Enable Spot & Margin Trading'(이미 현물 매매에 쓰는 권한). 바이낸스 문서상 예치·환매는 TRADE 유형이며 따로 체크할 Earn 권한은 없습니다. `/selftest`가 접근을 점검합니다.
  - 끄면 남은 예치금은 다음 리밸런싱 때 전부 현물 지갑으로 돌려받습니다.
  - 모의 모드는 바이낸스 Earn API를 부르지 않고, 가상 잔고에 연 `spot_cash_yield`(기본 3%)로 이자만 쌓습니다. `backtest_mix`도 켜져 있으면 현물 현금에 이자를 반영합니다.
  - 기록: `/export` CSV에 '이자예치'·'이자환매', `/spot`에 예치 잔고·연 이율·누적 이자.
  - 현물 지갑과 유연 USDT 예치금은 봇이 전부 운용합니다(직접 넣어 둔 유연 USDT도 현물 자금으로 계산). 따로 보관할 돈은 다른 곳에 두세요.

## v2.2 변경점
- **현물 BTC 추세 게이트**: 매일 리밸런싱 때 BTC 신호(20·60·120·250일 중 오른 기간 비율)가 `spot_btc_gate_min`(기본 0.5 = 2/4) 미만이면 BTC를 뺀 코인의 목표 비중을 0으로 합니다. BTC 비중은 그대로이고, BTC 일봉이 250일치보다 적으면 적용하지 않습니다. 실전과 백테스트가 같은 코드(`spot_strategy.target_weights`)를 씁니다.
- 참고(현물만, 2020-01 ~ 2026-10): 연 +50% → +56%, 최대낙폭 -33% → -29%. 2020~2023, 2024~2026 두 구간 모두 개선. 다른 전략 숫자는 바꾸지 않았습니다.
- 설정: `/set spot_btc_gate true|false`, `/set spot_btc_gate_min 0.5`(0~1). 다음 09:05 리밸런싱부터 적용.
- `/spot`과 아침 브리핑에 "BTC 신호 n/4 · 알트 허용/차단" 줄을 추가했습니다.

## v2.1 변경점
바이낸스 실제 데이터(2020-01 ~ 2026-10, 6종목, 실제 펀딩비)로 다시 검증한 결과입니다.
- **선물 돌파 기간 20봉 → 40봉, 추적 손절 6 ATR → 5 ATR.** 기존 규칙은 2024년 이후 연 +1%·최대낙폭 -49%로 우위가 사라졌습니다.
  2020~2023 / 2024~2026 두 구간 모두에서 30~45봉 × 5 ATR 근처가 고르게 더 좋았습니다(우연히 맞은 한 점이 아님).
  선물만: 연 +59% → +87%, 최대낙폭 -50% → -46% (2020~). 단, 2023년 한 해는 기존 규칙이 더 좋았습니다.
- 바꾸지 않은 것(검증해 보니 이득이 잡음 수준이거나 손해): 숏 허용, 종목 12개로 확대, BTC 추세 필터, 펀딩비 필터, ADX·손익분기 조정, 낙폭에 따른 자동 위험 축소, 현물 전략 전체.
- **백테스트가 실제 펀딩비 기록을 씁니다**(못 받으면 예전처럼 추정치). 상승장에는 롱 펀딩비가 커서 예전 추정치보다 결과가 낮게 나올 수 있습니다.
- **위험 단계 '안정'의 1회 위험 3% → 2%** (기본·공격과 차이가 나도록). 단계 설명의 수치도 새 결과로 바꿨습니다.
- **월간 리포트**: 매월 1일 09:10 KST에 지난달 총자산 변화, 같은 기간 BTC 보유 수익률, 선물 성적, 최근 30건 기준 선물 점검을 보냅니다. `/report`, `/report 이번달`. 끄기: `/set monthly_report false`.
- 거래소 손절이 먼저 체결된 직후 봇이 청산하려다 거절(-2022)되면, 경보 대신 손절 체결로 정상 기록합니다.
- 업데이트 직후 보유 중인 선물 포지션은 새 추적 폭(5 ATR)으로 손절이 올라갈 수 있고, 이미 그 선을 넘었다면 바로 청산됩니다.

## 설치 (서버에서 한 번)
```
U=https://github.com/<아이디>/<저장소>/raw/main/trendhunter.zip
cd ~ && curl -fsSL -o th.zip "$U" && python3 -m zipfile -e th.zip ~ && bash ~/trendhunter/install.sh "$U"
```
- 파이썬 표준 라이브러리만 사용(추가 설치 없음), Ubuntu 22.04/24.04, python3 3.8+
- 키는 `~/trendhunter-data/secrets.json` (권한 600)에만 저장됩니다. 코드에는 비밀정보가 없습니다.
- 처음엔 모의(PAPER) 모드로 시작합니다. 실전 전환은 텔레그램 `/live`.
- API 키 권한: Enable Futures, Enable Spot & Margin Trading, Permits Universal Transfer. **출금 권한은 끄고**, 서버 IP만 허용.

## 텔레그램 명령 (추가분)
